# Требования

Дата анализа: 2026-10-13

## Ограничения

| ID        | Требование                                                                                                                                                                          | Проверка                                                  |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| REQ-C-001 | Приложение использует React; язык реализации TypeScript принят как проектное допущение.                                                                                             | Проверка сборки и типов.                                  |
| REQ-C-002 | Приложение отправляет и отображает только текстовые сообщения.                                                                                                                      | Нет отправки медиа; входящие события фильтруются по типу. |
| REQ-C-003 | API host берется из `import.meta.env.VITE_API_URL`, если он задан; иначе используется `https://api.green-api.com/v3`. Пользователь вводит только `idInstance` и `apiTokenInstance`. | Проверка сборки с env и fallback; проверка формы.         |
| REQ-C-004 | Взаимодействие с GREEN-API выполняется методами `CheckAccount`, `SendMessage`, `ReceiveNotification` и `DeleteNotification`.                                                        | API-клиент покрыт мок-тестами.                            |

## Функциональные требования

| ID        | Требование                                                                                | Acceptance criteria                                                                                                                                                           |
| --------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-F-001 | Пользователь вводит `idInstance` и `apiTokenInstance` для текущей сессии.                 | AC-001: оба обязательных поля валидируются, `idInstance` содержит только цифры [SRC-007]; учетные данные не сохраняются в `localStorage` и не попадают в логи.                |
| REQ-F-002 | Пользователь создает чат по международному номеру телефона.                               | AC-002: допускаются только 11 или 12 цифр для номеров РФ/РБ [SRC-005]; пустой и некорректный ввод не вызывает API.                                                            |
| REQ-F-003 | Приложение проверяет номер через GREEN-API и использует возвращенный `chatId`.            | AC-003: при `exist: true` создается чат с `chatId`; при `exist: false` показана ошибка без создания чата [SRC-005].                                                           |
| REQ-F-004 | Пользователь отправляет текст в выбранный чат.                                            | AC-004: пустой текст не отправляется; длина не превышает 4000 символов [SRC-004]; успешный вызов отображается как принятый API, не как гарантированно доставленный [SRC-004]. |
| REQ-F-005 | Приложение получает сообщения через HTTP API GREEN-API.                                   | AC-005: ReceiveNotification вызывается последовательно; поддерживается параметр `receiveTimeout` в разрешенном диапазоне 5–60 секунд [SRC-007].                               |
| REQ-F-006 | Приложение показывает входящее текстовое сообщение в соответствующем чате.                | AC-006: отображается только событие `incomingMessageReceived` с `messageData.typeMessage: textMessage`; текст и `chatId` читаются из подтвержденных полей схемы [SRC-009].    |
| REQ-F-007 | После обработки полученного уведомления приложение подтверждает его удалением из очереди. | AC-007: `DeleteNotification` получает `receiptId`; уведомление считается подтвержденным только при `result: true` [SRC-008].                                                  |
| REQ-F-008 | Пользователь может отключить сессию и polling.                                            | AC-008: учетные данные очищаются из памяти; активный запрос отменяется, новые запросы не запускаются.                                                                         |
| REQ-F-009 | Приложение сообщает об ошибках сети и API.                                                | AC-009: ошибки валидации, 4xx, 5xx, таймаут и отсутствие сети дают понятное состояние; секреты в сообщениях об ошибках скрыты.                                                |

## Зависимости

- Для отправки по номеру требуется `CheckAccount`, чтобы получить `chatId` для последующей отправки и приема ответов [SRC-005, SRC-010].
- Получение входящих уведомлений требует включенной настройки `incomingWebhook` и пустого `webhookUrl` у инстанса [SRC-006].
- Пользователь предоставляет значения инстанса через форму; в репозитории секретов нет.
- `VITE_API_URL` доступен клиентскому коду как публичный host; `ID_INSTANCE` и `API_TOKEN_INSTANCE` остаются без `VITE_` и не читаются приложением [SRC-014].
